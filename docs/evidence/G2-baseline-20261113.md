# libde265 G2：native A/B 与 riscv64 交叉基线（2026-11-13）

- 上游：`strukturag/libde265` @ `4fb298e`
- 构建：cmake，`BUILD_SHARED_LIBS=OFF -DENABLE_SDL=OFF -DENABLE_ASSEMBLY=OFF`
- 探针：`test/pkg_libde265.c`，解码 `test/data/tiny-64x64.265`

| 项 | native | riscv64 (rv64gc) |
|---|---|---|
| 帧数 / 输出字节 | 10 / 61440 | 同左 |
| 像素哈希 | `fnv_px=cf67fb9981835c6a` | 同左 |

## 语料从哪来（这是本项最大的坑）

libde265 仓库**不带任何 HEVC 测试流**，没有码流就没有解码路径可测。做法：
用 x265（`bitbucket.org/multicoreware/x265_git`，Release_4.1）在容器里把固定 YUV 编码成
`tiny-64x64.265`（4828 B，sha256 `5a7a4a8f5a891dc5…`），把**这一个文件**提交进本仓库，
x265 本身不进工程、不参与 A/B——它只是"造语料的一次性工具"。参数写在这里以便复现：

```
x265 --input-res 64x64 --fps 25 --frames 10 --crf 23 --preset veryfast \
     --keyint 10 --min-keyint 10 --no-wpp --bframes 0
```

## 两个 API/链接坑

1. **`de265_get_image_plane_stride` 不存在**：stride 是 `de265_get_image_plane(img, c, &stride)`
   的第三个出参回填，别按别的解码库的习惯去猜函数名——先 `grep` 头文件。
2. **C 探针要 C++ 驱动链接**：libde265 内部有 C++（`nal-parser.cc`、`de265.cc` 用到
   `std::__throw_length_error`），C 链接器会报一串未定义符号。同 zimg：`LINKER_LANGUAGE CXX`
   + `project(... C CXX)`。
